# System Monitor — Agent Instructions

## Project Structure
- **Root files**: `main.py` (app + tray menu + collector thread), `metrics.py` (retrieval), `theme.py` (design tokens), `painter.py` (pure renderer), `history.py` (ring buffer + CSV), `overlay.py` (panel window), `settings.py` (persisted preferences), `tests/`
- **PyInstaller**: `Monitor.spec` is the build; `build_exe.bat` only invokes it. Do not add a second description of the build — a hand-rolled `--add-data` list beside the spec is how `overlay.py` and `metrics.py` came to be copied next to the exe as inert data files.
- All Python modules live at root, not in a subdirectory.

## Running
- **Setup**: `python -m venv .venv && .venv\Scripts\activate && pip install -r requirements-dev.txt` (runtime deps only: `pip install -r requirements.txt`)
- **Run**: `python main.py`
- **Build exe**: `build_exe.bat` → outputs `dist\Monitor.exe`
- **Dependencies**: `psutil`, `PyQt6`, `pynvml` (NVIDIA), `wmi` (the GPU fallback only, and only on a machine with no usable NVML handle)

## Key Gotchas
- **Sampling is off the GUI thread**: `main.py`'s `Collector` is a `QThread`, and it **builds** the probe there rather than being handed one. `import wmi` is not a passive import — it runs `GetObject("winmgmts:")` at module scope — and `metrics._wmi_video_controllers()` opens a `wmi.WMI()` COM connection, and a COM connection belongs to the thread that opened it: a connection opened on the GUI thread and queried on the worker used to raise `RPC_E_WRONG_THREAD` (0x8001010E) on the first query of every launch. With `CpuClockProbe` gone the fallback opens and closes its connection inside one call on one thread, so the fault is no longer reachable through it — but the factory is still what keeps it that way, and it is also what keeps any future eager COM construction out of `SystemProbe.__init__`. `Collector.run()` also does `pythoncom.CoInitializeEx(pythoncom.COINIT_APARTMENTTHREADED)` / `CoUninitialize` around the loop — `import wmi` runs `GetObject("winmgmts:")` at module scope, so the first import opens a connection from whatever thread asks for it, and pywin32's own lazy init is what supplies the apartment today (measured: a bare `threading.Thread` *can* import wmi, then prints the IUnknown line) — so that call is defensive rather than the fix, and on its own it is *not* a fix, because both apartment models were measured to still fail on a connection opened elsewhere. So `Collector` takes a **factory**; passing an instance is a bug. Release the probe before `CoUninitialize`: releasing it after the apartment is gone **aborts the process** with 0xC0000409, with "Win32 exception occurred releasing IUnknown" on stderr the last thing it manages to say. **An exception out of `Collector.run()` is fatal to the process** — it is not catchable from the outside, and it measured `-1073740791` with **zero** log records — so `run()` wraps the factory call *and* the sample loop in `try/except Exception` and `logger.exception(...)`. `SystemProbe.__init__`'s `import psutil` is not guarded, and building the probe on this thread moved it out of `main()`'s `try/except`; with the handler, the panel simply stops updating and the status dot goes neutral. (The CPU clock's own cost — ~140 ms of process CPU per sample, ~7% of a core, and ~530 ms of wall time, mostly the thread *blocked* in the WMI provider rather than computing — went with the clock.)
- **A stale snapshot goes neutral.** `Snapshot.ts` is written and read by nothing except the CSV, and the header carries no age figure at the user's explicit request — so the status dot is the panel's only evidence that its numbers are current. Beyond `theme.STALE_AFTER_S` (three ticks, 6 s; the boundary is exclusive) the dot is `theme.NEUTRAL`, the colour a panel with no data already uses, and no new token exists for it. `paint()` takes `now` as an argument for this; the test funnel passes the snapshot's own `ts`, which is what keeps the goldens (all `ts=1000.0`) byte-identical. The panel repaints from its own `QTimer` every `TICK_MS` — `apply_snapshot()` is the only other thing that calls `update()`, and a wedged collector sends no snapshots, so without it the rule would be true and invisible. **What a wedged collector therefore looks like:** every row keeps its last value *and its last colour*, so a stale panel is pixel-for-pixel what an all-dashes panel looks like except for the dot — and the dot is the quietest thing on screen. That is the price of the user's decision to remove the age figure, and it belongs here rather than in a code change: there is nothing in the panel that says how old the numbers are.
- **There is exactly one WMI query left, and it is not a projection.** `metrics._wmi_video_controllers()` uses `wmi.WMI().Win32_VideoController()`, the convenience wrapper that pulls every property of every instance — 44.6 ms, against 6 ms for a projection. It is affordable *because* it runs at most once a minute (`WMI_FALLBACK_REFRESH_S`) on a machine with no usable NVML handle, not because the wrapper is cheap. If anything starts querying WMI more often, project it first: `Win32_Processor` measured 1044 ms that way against 6 ms projected, and `Win32_PerfFormattedData_Counters_ProcessorInformation` 481 ms against 353 ms. A projection naming a property the repository lacks is rejected outright, which is why the two per-tick queries the clock probe used projected `MaxClockSpeed` and `ProcessorFrequency` separately.
- **The no-NVIDIA path must not query WMI per tick.** With no NVML handle, `GpuProbe.read()` answers from a cache refreshed every `WMI_FALLBACK_REFRESH_S` (60 s), not by re-opening a COM connection and running `Win32_VideoController()` every two seconds — that was 300 real queries (44.6 ms each) per ten minutes on exactly the machines the spec's acceptance criterion 5 targets. Re-checked on a slow interval rather than cached for the process's life, because a WMI service that was down at startup would otherwise leave the GPU row dashed for the session. The cache is copied per read; handing the dict out would let a caller change the next answer.
- **REMOVED with the CPU clock — `_reading(value, floor=, ceiling=)` was the one gate, and it covered only the CPU clock** — three call sites, all in `CpuClockProbe`: the nominal from WMI, the nominal from the psutil fallback, and the performance ratio. It required finite and strictly positive, with the optional bounds named at the call site. The bounds in force: `_PERF_RATIO_MIN = 10` and `_PERF_RATIO_MAX = 200` on `PercentProcessorPerformance` (a percentage of nominal; 100 is nominal, above it is turbo, and nothing clocks a CPU at twice nominal), and `_NOMINAL_MAX_MHZ = 20_000` on the nominal clock (the fastest core in production is ~5.7 GHz). A row outside the ratio band was skipped, not voided, so one garbled core did not cost the others. So there is **no plausibility gate on any reading left, and that is a known gap**: net rates, GPU readings (`GpuProbe.read`) and the RAM/CPU percentages (`SystemProbe.sample`) are trusted rather than validated — psutil and NVML return percentages, not raw counters. The one derived value with no bound at all is the net rate, which is why `_format_rate` saturates at one terabyte rather than trusting its input.
- **A cumulative counter's discontinuity is `None`, never a number.** In both directions: a counter that goes backwards (adapter re-enumerated) and an adapter set that changed (one appeared carrying its boot-time total, or one vanished leaving a missing term). Both unmeasure that tick *and* drop the EMA average, or a pre-event peak blends into the next real reading at 0.35/0.65 and decays over five ticks. The set comparison comes **before** the elapsed-time guard, because an adapter arriving on a backwards clock is still a churn — and a non-churn tick with no elapsed time keeps its average, since nothing discontinuous happened.
- **REMOVED with the CPU clock — only the per-processor perf rows were averaged.** `_Total` was a summary *of* them and reads 100 on an idle machine.
- **REMOVED with the CPU clock — psutil `cpu_freq()` is the nominal clock on Windows, not the live one.** Three consecutive calls returned `current == max == 4501.0`, which is why it was never published. Nothing reads it now.
- **GPU metrics**: Require NVIDIA GPU. Falls back to WMI heuristics which are approximate.
- **sys.path**: `main.py` appends its own directory, and `tests/conftest.py` puts the root on the path for the suite. If adding modules, ensure they're importable from root.
- **UI sizing**: there is nothing to size. `painter.py` is a pure function from snapshot to `QPainter` commands and `overlay.py` hands it a fixed-size canvas, so there is no widget whose text can clip and no `adjustSize()` to call. A metric that could not be measured renders `--`, which is a fixed-width string; a metric that was measured renders its own digits.
- **Mouse controls**: drag moves the panel, left double-click snaps it back to the top-right corner, wheel adjusts opacity, right-click opens the tray menu, middle-click quits. A tray double-click also snaps it back.
- **Colour encodes load, and only load**: a row is calm blue until it crosses a threshold, so there is no random-colour mode to preserve and none to reintroduce. Three states, not two — percentages and RAM/VRAM warn at 80 and go critical at 95, GPU temperature warns at 70 °C and goes critical at 80 °C. An unmeasurable metric is `--`, never a guess.
- **Logging**: `app_debug.log` is rotating (512 KB, 2 backups) and carries lifecycle and errors only; the per-metric probe chatter is filtered to WARNING and above. `metrics.log_fault()` writes a record for a source's **first** fault, for a **different exception type**, and for a fault that followed a full `LOG_INTERVAL` of health — and nothing else, so a source that fails continuously writes exactly one record for the life of the process. `clear_fault()` on each call site's healthy path is what makes the third of those reachable: a source that answers never calls `log_fault`. `LOG_INTERVAL` is **300 s**, not the spec's minute, because it no longer paces a summary — at 60 s a flapping source still earned a record a minute and five of them measured 6,900 B per ten minutes against the spec's 5 KB ceiling. At 300 s the worst case the rule permits is 2,655 B, one continuously broken source is 441 B, and five are 2,130 B. The full `exc_info` dump goes on the first record for a type and on the line after every other: the traceback says where, and it follows the type because the raising line moves with it. A fault whose *message* varies per occurrence does *not* reopen it, or the bound would not be a bound. `metrics_history.log` is an opt-in CSV trace, off by default, toggled from the tray menu. Both sit beside the executable, not in the working directory, and both are gitignored.
- **One home for the alpha range**: `theme.MIN_ALPHA` / `MAX_ALPHA` / `DEFAULT_ALPHA`. `settings.py` imports them; it used to restate the bounds, so the loader and the wheel could disagree about what opacity is legal with nothing to report it. `Settings.alpha`'s default is `theme.DEFAULT_ALPHA` and the loader validates it with the same `_alpha()` as a value read from disk.
- **Window**: Frameless, translucent background, stays on top, positioned top-right of screen. `apply_window_flags()` states all three flags at once and is called once, from `__init__`. `WindowStaysOnTopHint` is **unconditional**: it used to be added only while `settings.always_on_top` was true, which was also that setting's default, so unticking removed a flag that was not what kept the panel visible — a `Qt.Tool` window is topmost anyway — and the user reported the row as doing nothing. The setting, its validator and its tray row are gone; the z-order is not a preference.
- **No system backdrop, ever**: `painter.py` draws the drop shadow *outside* `panel_rect()`, so the 8 px bleed margin (`Layout.bleed`) has to stay transparent or the shadow has nothing to fade into. A DWM backdrop material is composited behind the **whole window rect**, so it fills that margin with an opaque, hard-edged, **square-cornered** slab and the shadow disappears with it. Measured here (Win11 25H2, the real panel over a saturated window): 538,328 of 547,600 pixels inside the rect changed. Mica (2) and `AUTO` (0) fill the same rect, and `DWMWA_BORDER_COLOR = DWMWA_COLOR_NONE` changed **0** pixels — the slab is the material, not a border at the window edge. So there is no value to pick, which is why the acrylic setting, its ctypes plumbing and its tray row were removed rather than retuned. `tests/test_main.py::test_no_menu_action_can_put_a_system_backdrop_behind_the_panel` triggers every menu action and reads the live attribute back off the handle, and `::test_no_application_module_can_reach_a_dwm_backdrop_attribute` walks every module's AST for a DWM name (so a re-added helper the menu cannot reach still fails). Both exist because the failure mode is a border nobody drew, with no code path anyone would grep for.
- **The topmost position is re-asserted, not just declared**: `apply_window_flags()` states the flag once and Windows does not keep that promise afterwards — a switch into fullscreen, a launcher or another always-on-top window all bury the panel. So `MonitorApp._watch_topmost()` starts a `QTimer` parented to the panel at `TOPMOST_REASSERT_MS` (1000 ms) whose slot calls `assert_topmost()` → `SetWindowPos(hwnd, HWND_TOPMOST, 0, 0, 0, 0, SWP_NOMOVE | SWP_NOSIZE | SWP_NOACTIVATE)` (flag word `0x0013`). Every flag is deliberate: NOMOVE and NOSIZE keep the position and size the user chose, NOACTIVATE stops the panel taking the keyboard off a game, and **SWP_SHOWWINDOW and SWP_NOZORDER are deliberately absent** — the first would put a hidden panel on screen, the second would make the call a no-op that looks like it works. Measured over 20,000 real calls on the real window: 45.07 µs wall, 27.34 µs CPU, so the cadence is 86,400 calls a day = 2.4 s of CPU = 0.024 % of one core, and a test holds the interval to 0.05 % of a core rather than to taste. Skipped while `panel.isVisible()` is false, so a hidden panel is never shown, moved or focused. A fault goes through `metrics.log_fault`/`clear_fault` under the name `"topmost re-assertion"` — an unthrottled log line on a one-second timer is 86,400 records a day. Tests that need `isVisible()` true without a window on the desktop use `WA_DontShowOnScreen`, which leaves `IsWindowVisible` false. **Exclusive fullscreen is the one case none of this can fix** (the game owns the display output, so nothing composites over it); borderless fullscreen is an ordinary maximised window and is fine. It is documented in the README rather than worked around, and **no code hides the panel during a game** — the user asked for it never to disappear on its own.
- **Tests**: never run under `QT_QPA_PLATFORM=offscreen` — `tests/conftest.py` strips it, because Qt on Windows has no font database there and every glyph rasterises as tofu, which the golden images would lock in.

## Adding Metrics
Four places, and all four or the trace and the panel disagree:
1. `metrics.py` — the retrieval, plus a field on the frozen `Snapshot`.
2. `Snapshot.CSV_COLUMNS` — `test_csv_columns_covers_every_declared_field` fails if a declared field is missing from it, and every value is read back **by declared index** by `test_every_csv_column_holds_the_value_that_names_it`, so the row and the header cannot drift apart.
3. `theme.py` — a `MetricSpec` in `METRICS` if the row is a *metric* (i.e. it has warn/critical thresholds and gets coloured). Something informational belongs in the header instead and must stay out of `has_any_data()`, or it lights the status dot.
4. `painter.py` — the row's `_format_value` / `_format_aux`, or `_format_net` for a header reading.

Regenerate the goldens after any renderer change and **look at them**:
`$env:MONITOR_REGEN_GOLDEN=1; python -m pytest tests/test_painter.py` (PowerShell — the
`VAR=1 cmd` form in the test docstrings is bash and does not work here).
